# PR 与 ISSUE 协作规范（验收标准）

> 本文承载协作的**规则与约定**，经用户裁决落定，适用于本仓全部 ISSUE 与 PR。
> 目的只有一个：**让评审者（用户）以最小精力建立对结果的信任**。
> 与 Gitea 平台操作口径（身份、凭据、标签、状态机）配合使用时，以根级技能
> `gitea-workflow` 为操作手册，以本文为验收门槛。

## 1. PR 建档规范

PR **创建时**即挂齐元数据，不允许"先建后补"：

- 标签：`type/*` 恰好一个、`comp/*` 按需、`src/*` 恰好一个；
- 里程碑：所属里程碑必挂；不属于任何里程碑的 PR 不允许存在；
- 关联 issue：正文 `Closes #n` 或明确说明关联关系；
- 状态标签随流程推进（`status/in-progress` → `status/verified`）；
- **正文首节必须回答「解决了什么问题」**：用评审者（用户）视角陈述交付物
  （加了什么能力、修了什么缺陷、改变了什么行为），不是提交清单的复述。
  评审者读首节 30 秒内必须能回答"这个 PR 给我带来了什么"。

平台元数据可由 bot 经 API 代设，不设为任何执行者的额外负担——但**缺失即 PR 不及格**。

## 2. 证据标准

- **视觉性/用户可见特性**：验收证据必须来自**游戏内真实导出链路**，
  并注明：世界与场景、导出产物哈希、提交号、渲染模式（本色 / 参与光照）、
  机位参数。截图需能直接查看、可并排对照。
- **UI 侧截图（web 端渲染/悬停/统计/Tooltip/点选等）一律以真实导出产物为输入**：
  把游戏内真实导出的文件加载进 web 应用再交互截图。
  合成 fixture 场景喂给 UI 的截图**不是验收证据**，只能作开发过程旁证且必须标注。
  任何"fixture 场景 + UI 交互"的截图出现在验收证据位 = 直接打回。
- **fixture（手工构造数据）证据**：必须显式标注"夹具证据 + 使用理由"，
  且**不得**作为用户可见特性的唯一验收依据。
- 断言是旁证，图是主证：执行者不得以"断言全绿"替代证据图。
- 证据自包含：只凭平台正文与附件即可复核；本地路径（尤其 `temp/`）仅作补充。

### 2.1 证据呈现规范（验收位图片的硬性格式）

- **内嵌，不是链接**：验收位截图必须以 `![图说](/attachments/<uuid>)` 形式
  **直接内嵌在正文对应小节**，评审者滚动页面即可看图，不需要点开任何附件链接；
- **每张图配两行图说**：① 这张图证明哪条功能/判据；② 看图要点（看哪里、
  什么叫对、什么叫错）；
- **功能 → 证据映射表**：正文必须有表格，逐行列出「验收项 | 证据图（内嵌位置） |
  验证方法（评审者 30 秒内可执行的动作）」；评审者按表逐行看图即完成复核，
  不许让评审者自己在附件堆里做对应关系；
- 附件列表仍可保留（原始产物/日志/哈希清单），但它是**档案**，不是证据呈现。

## 3. 粒度规范

- **按可独立合并性拆分，不按 issue 数拆分。** 每个 PR 必须能独立通过评审与合并。
- **禁止 stacked 拆分**（PR 的 diff 包含未合并前置 PR 的提交），
  除非每个前置 PR 本身独立可合并且已先行合入。
- 强耦合交付 = **单分支、单 PR、内部分提交**，正文给逐提交评审指引。
- 一棵工作树对应一个交付单元；不为人为拆分创建多余工作树。

## 4. 验收成本预算

每个 PR 正文必须含「**人类 5 分钟复核路径**」小节：

- 看哪几张图、点哪个按钮、对照哪条判据；
- 复核所需的一切材料在正文或附件内可达；
- 超过 5 分钟无法完成复核的 PR 视为不及格，打回重整。

## 5. 平台写作权限规范

ISSUE 与 PR 的**创建与撰写**是调度层权力：

| 角色 | ISSUE | PR |
|---|---|---|
| 团队领导人（Lead） | ✅ | ✅ |
| 项目负责人（队友/调度者） | ✅ | ✅ |
| 子代理（执行模型） | ❌ | ❌ |

- 子代理严禁任何 Gitea 写操作；不得向子代理的提示中注入 Gitea 凭据；
- 子代理产出（代码、分析草稿、证据素材）以文件或消息回传项目负责人，
  由项目负责人**验收后**决定是否、以及如何落平台；
- ISSUE/PR 承载的是判断与承诺（需求定性、根因结论、验收标准、证据组织），
  必须由对交付物负责的角色亲自撰写。

## 6. 违反处置

不满足第 1–4 条的 PR 不予评审，直接打回并注明缺失项；
不满足第 5 条的平台内容视为无效留痕，由 Lead 清理并重新登记。
